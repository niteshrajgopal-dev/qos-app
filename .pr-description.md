# QOS-115: follow-up - product status, real sidebar counts, empty states

Follow-up to merged PR #20 addressing three QA issues found on dev (tenant `0fe2c09b-e07e-4c0c-a3e1-254773eed5b9`, Quotes).

## Changes

### 1. Product Status Fix

**Problem**: All 151 products showed as Draft (Active 0), but ~147 are live on the storefront through the published menu.

**Root Cause**: The FineDine import creates products with `status: 'draft'` (default). When a menu is published via `publishDraftMenuToLocations`, the menu status is set to `active`, but products remain `draft`. The `catalogue_products.status` field was never updated to reflect that products are live on the storefront.

**Fix**: Updated `publishDraftMenuToLocations` in `src/lib/catalogue/menu-publish.ts` to automatically activate products when they're first published:
- After a successful publish, queries for all `draft` products in the published menu
- Updates their status to `active`
- Records the count in the audit log

**Why this approach**: Product status should reflect storefront visibility. A product is "active" when it's available to customers via any published menu. This is the smallest correct fix—it updates status at the point when a product becomes live, without requiring separate manual activation.

**Migration**: Added idempotent migration `0036_activate_published_products.sql` that:
- Only touches `draft` products that appear in at least one `catalogue_menu_live_revisions` (published menu)
- Does NOT touch archived products or products not in any published menu
- Safe to run multiple times (WHERE clause filters on `status = 'draft'`)

**Verification**: On Quotes tenant after migration:
```sql
-- Before: all products draft
SELECT status, COUNT(*) FROM qos.catalogue_products WHERE tenant_id = '...' GROUP BY status;
-- Expected: ~147 active, ~4 draft (including prd_quotes-demo-latte_dee2bfd7)

-- Products in published menus
SELECT COUNT(DISTINCT cp.id) FROM qos.catalogue_products cp
  INNER JOIN qos.catalogue_menu_section_products cmsp ON cmsp.product_id = cp.id
  INNER JOIN qos.catalogue_menu_sections cms ON cms.id = cmsp.section_id
  INNER JOIN qos.catalogue_menu_live_revisions cmlr ON cmlr.menu_id = cms.menu_id
WHERE cp.tenant_id = '...' AND cp.status = 'draft';
-- Expected: 0 after migration
```

### 2. Real Sidebar Counts

**Problem**: Sidebar still showed mock badges (Products 1583, Menus 6, Modifier groups 24, Categories 18) from `src/mocks/platform.ts`.

**Fix**: 
- Created `src/lib/catalogue/counts.ts` with `getCatalogueCounts` function that returns real per-tenant counts
- Counts only `active` products and modifier groups (matches display logic)
- Counts all menus and categories regardless of status
- Added `/api/tenants/[tenantId]/catalogue/counts` endpoint
- Updated `StaffAppShell.tsx` to fetch real counts on mount and display them in sidebar
- Removed dependency on `NAV` mock—rebuilt nav structure inline with real counts

**Verification**: Sidebar badges now show actual counts per tenant. If counts fail to load, badges are hidden (no mock fallback).

### 3. Empty States

**Problem**: When search matches nothing or a tab is empty, the UI shows a blank table.

**Fix**: Updated `src/components/platform/catalogue-products-list.tsx`:
- **No search results**: Shows EmptyState with "No products match your search" message and "Clear search" button in place of table
- **Empty tab**: Shows EmptyState with tab-specific message:
  - Active: "No active products. Active products will appear here once published."
  - Drafts: "No draft products. Products you create or import will start as drafts."
  - Archived: "No archived products. Archived products will appear here."
- Uses existing design-system `EmptyState` component
- Text is modest, sentence case, no all caps
